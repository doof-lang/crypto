# RSA implementation validation

Date: 10 October 2026. The API and three desktop backends are implemented;
full cross-platform acceptance is not yet complete.

## Executed checks

- macOS public API: 47 tests passed (38 existing crypto tests plus nine RSA tests).
  RSA coverage includes independently generated exact signatures for 2048/3072/
  4096-bit keys, all four key encodings, empty/binary/UTF-8 messages, source wipe,
  repeated signing, wrong same-size public key, malformed signatures, PEM/DER
  truncation/trailing data, encrypted keys, non-RSA/RSA-PSS keys, and input policy.
- Standalone Apple Security and OpenSSL 3 EVP backend adapters: eight concurrent
  threads sharing signing/verifying keys and 100 repeated imports/signs passed
  under AddressSanitizer and UndefinedBehaviorSanitizer on macOS. Provider
  libraries themselves were not sanitizer-instrumented. EVP execution on macOS
  does not establish Linux runtime acceptance.
- Windows native bridge and DER reader: MinGW C++20 syntax checks with
  `-Wall -Wextra -Werror` passed (runtime headers treated as system includes).
  Windows runtime operations have not been executed.
- Wasm: all 47 public API tests passed after adding Apple Security-backed
  `wasi_snapshot_preview1.random_get` to the compiler's test host. The dedicated
  host fixture also passed all four tests, covering fresh instances, bounded
  randomness transfers, zero-length requests, and invalid memory ranges. RSA
  remains unavailable on Wasm; valid imports return `CapabilityUnavailable`
  while existing hashing, encoding, and randomness continue to work.

## Reproduction

From the crypto package:

```sh
DOOF_STDLIB_ROOT=/Users/andrew/develop/doof-stdlib doof test .
DOOF_STDLIB_ROOT=/Users/andrew/develop/doof-stdlib doof test . --target wasm
```

Native adapter (macOS):

```sh
clang++ -std=c++20 -fsanitize=address,undefined -g -I. \
  -I/path/to/doof-lang/runtime tests/native/rsa-runtime.cpp \
  doof_rsa.cpp rsa_encoding.cpp doof_crypto.cpp \
  -framework Security -framework CoreFoundation -o /tmp/rsa-runtime
/tmp/rsa-runtime tests/fixtures
```

To exercise EVP on this host, explicitly define `DOOF_CRYPTO_RSA_EVP=1`, add
`pkg-config --cflags libcrypto` and `pkg-config --libs libcrypto`, and omit the
Apple frameworks. Normal package selection uses Apple Security on macOS and
optional libcrypto detection on Linux.

Fixtures are disposable, public test keys generated by OpenSSL. The message for
stored signatures is exactly `Doof RSA interoperability fixture`, with no newline.
The fixture signature command is `openssl dgst -sha256 -sign <key> -sigopt
rsa_padding_mode:pkcs1`, encoded with `openssl base64 -A`. Production operations
and the Doof tests do not invoke OpenSSL or load fixture files at runtime; the
Doof fixture module embeds them for deterministic testing.

## Remaining gates

- Windows and Linux public API/runtime parity against the exact same fixtures.
- Linux optional-dependency selection with available and absent development
  metadata; hashing plus valid RSA import on the unavailable stub.
- Explicit no-OpenSSL-executable consumer run and installed/offline bundle check.
- Additional native invalid-component, upper-size/exponent/multi-prime boundary,
  failure-path leak, and serialization-exclusion checks.

The local Linux Container setup has no installed kernel or images, so it could
not provide Linux runtime evidence. These outstanding checks prevent calling the
complete release acceptance matrix passed.
